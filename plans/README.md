## How to execute (read first)

You may have zero prior context. Follow this exactly:

1. **Each table row maps to a self-contained plan file** at
   `plans/<NNN>-<slug>.md` (e.g. row 013 → `plans/013-react-error-boundary.md`).
   That file — not this index — is the source of truth for what to change. Open
   it and follow it step by step.
2. **Only act on rows whose Status is `TODO`.** Skip `DONE`, `REJECTED`, and
   `BLOCKED` rows — do not re-do or "verify" them.
3. **One plan at a time.** Do not batch multiple plans into one change.
4. **Establish a baseline before your first plan**: run
   `npm ci --no-fund --no-audit`, then `npm test`. If the suite is already
   failing on `main`, note which tests fail _before_ you start, so you can tell
   pre-existing failures from ones you introduce. (If the baseline is broken,
   stop and report — do not build on a red baseline.)
5. **Per plan**: run the plan's "Drift check" command first; work on the branch
   the plan names; run every verification command and confirm its expected
   result; honor the plan's STOP conditions (stop and report rather than
   improvise); do NOT push or open a PR unless the operator told you to.
6. **When a plan is done**, update its Status cell in the table below (use the
   status values on the legend line) — unless a reviewer dispatched you and said
   they maintain this index.

- **SEC-05** (error details in sub-500 responses): by-design for a local desktop app with no public exposure.

- **DX-09** (custom gitleaks package): the real `gitleaks` binary already runs in CI via `npx --yes gitleaks detect`. The local wrapper is a convenience shim.
- **PERF-5** (date-exact analytics cache keys): the analytics cache TTL defaults to 0 (disabled). Cache code exists but is not active by default; optimizing disabled code has no impact.
- **BUG-07** (three transaction snapshots in daily_close): single-user desktop app; concurrency between nightly job and user operations is negligible.
- **PERF-6** (portfolio save read-all/write-all): inherent to the `JsonTableStorage` + `atomicBatchWrite` architecture. Changing it requires a storage-layer rewrite (L effort, HIGH risk) that doesn't justify the benefit for a single-user app with ~1000 transactions.

### From the 2026-07-01 deep audit

Subagents over-reported; these did **not** survive vetting against the real code:

- **"CRITICAL: API secrets committed to git"**: FALSE. `.env` is gitignored
  (`.gitignore:16`) and was never committed (`git ls-files .env` empty;
  `git log --all -- .env` empty). Only `.env.example` (empty placeholders) is
  tracked. No secret is in history; no rotation needed.
- **returns.ts prevPrice fallback (`:518`) & NAV accumulation (`:524`)**: FALSE.
  `prevDate` is only assigned after a price exists (the price-undefined branch
  `continue`s without updating it), so `priceMap.get(prevDate) ?? price` never
  hits the fallback; NAV accumulation is integer-cents addition, so no drift.
- **returns.ts first-date NAV zeroing (`:509`)**: not a bug. The synthetic
  benchmark starting at $0 when the first date carries no external flow is
  defensible (you can't invest $0); would need caller-semantics evidence to be
  a finding.
- **setCurrentPrices stale closure (`PortfolioManagerApp.jsx:420`)**: FALSE —
  `openHoldings` IS in the `useCallback` dependency array.
- **`parseFloat`→`toCents` "accumulation drift"** (`cash.ts:302`,
  `portfolio.ts:178,330`): overstated. Each amount is rounded to integer cents
  before accumulation, so there is no drift; only rare ≥3-decimal half-cent
  boundary values could round differently. Marginal — not planned.
- **`computeSharpeRatio` native-float math** (`returns.ts:1071`): a real
  decimal.js-discipline inconsistency but numerically negligible (~1e-14);
  not worth a plan.
- **nodemailer HIGH (GHSA-p6gq-j5cr-w38f)**: real `npm audit` hit (installed
  8.0.11; fix is the breaking 9.0.3), but the vulnerable message-level `raw`
  option is not used — `server/services/signalNotificationEmail.js` builds a
  structured message and sends it to the user's own SMTP. Low real severity for
  a local single-user app; the breaking bump is low-urgency hygiene, deferred.
- **"Surface swallowed async errors" (finding B)**: downgraded — the cited
  catches are already handled (`useDesktopSession` logs + runs a recovery path;
  `usePerformanceData` falls back to stale + raises an alert), benign
  best-effort (`usePersistentBenchmarkSelection` localStorage parse), or
  post-success refreshes (`PortfolioManagerApp.jsx:661,694`). Not worth a
  dedicated plan; the top-level error boundary (013) is the real resilience win.
- **God-module refactors** (`portfolio.ts` 1281 LOC, `returns.ts` 1155 LOC,
  `analytics.ts` 751 LOC): real structural debt but L-effort / MED–HIGH risk on
  money-critical code. Deferred to design/spike plans rather than blind
  refactors; not planned now.
